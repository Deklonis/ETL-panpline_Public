# Contacts ETL

Десктопное приложение (Python + PyQt6): превращает Word-список участников конференции в чистые данные и загружает их в базу контактов без дублей.

## Зачем

После конференции приходит Word-таблица, где компания и должность лежат в одной ячейке, телефон и почта в другой, а часть людей уже есть в базе. Для CRM-системы нужны ещё обращение и склонения. Вручную внесение данных в CRM занимает часы, приложение делает это за секунды, а человек только проверяет результат.

**Таблицы SQLite:**

| Таблица | Что хранит |
|---|---|
| `peopledb` | основная база людей |
| `data_company` | основная база компаний |
| `file_draft` | временный черновик, пока работа отложена |

## Как преобразуются данные

**Было** (строка из Word):

| ФИО | Компания, должность | Контакты |
|---|---|---|
| Кузнецова Марина Олеговна | Общество с ограниченной ответственностью «Северный Вектор»<br>Директор по стратегическому развитию | 8 (916) 305-41-29<br>marina.kuznetsova@example.com |

**Стало** (запись в реляционной базе данных):

| Поле | Значение |
|---|---|
| Компания | ООО «Северный вектор» |
| Id | 2812 |
| ФИО | Кузнецова Марина Олеговна |
| Обращение | Уважаемая Марина Олеговна |
| ФИО (дат. падеж) | Кузнецовой М.О. |
| Должность | Директор по стратегическому развитию |
| Должность (дат. падеж) | Директору по стратегическому развитию |
| Телефон | 89163054129 |
| Почта | marina.kuznetsova@example.com |
| Участие |  |
| Уже в базе? | нет |

Что делает Transform:
1. Чистит текст и делит ячейку на компанию и должность (по словарю должностей).
2. Достаёт телефон и почту регулярными выражениями.
3. Приводит название компании к единому виду.
4. Склоняет ФИО и должность (`pymorphy3`, `petrovich`) и подбирает «Уважаемый / Уважаемая».
5. Ищет человека и компанию в базе (см. ниже).
## Архитектура

Данные проходят четыре шага: **Extract → Transform → Проверка → Load**.

**1. Extract (чтение).** Программа открывает Word-файл, ищет там таблицу. Каждая строка таблицы превращается в список из 5 ячеек: номер, ФИО, «компания + должность», договор, «телефон + почта». Лишние пробелы убираются, текст приводится к нижнему регистру.

**2. Transform (преобразование).** Каждая строка из 5 ячеек превращается в готовую запись из 11 полей: номер, ФИО, обращение, ФИО в дательном падеже, компания, должность, должность в дательном падеже, телефон, почта, признак «уже есть в базе» и список конференций, где человек уже был. На этом шаге программа читает таблицу `peopledb`: ищет там человека и компанию, чтобы не создавать дубли, и берёт оттуда слова для распознавания должностей.
В файлах лежит специализированная версия базы данных. Приложение использует их как словарь, чтобы отделять должность от названия компании в строках из Word.

**3. Проверка.** Готовые записи хранятся в памяти и показываются в окне: слева компании, справа люди. Оператор проверяет данные. Если проверку нужно закончить позже, кнопка «Отложить» сохраняет записи в таблицу `file_draft`, а название файла и конференции в `settings.json`. При следующем запуске программа видит черновик и открывает его сразу.

**4. Load (загрузка).** По кнопке «Отправить» в базу записываются только новые люди, то есть те, кого не нашли на шаге 2. Если их компании ещё нет, она добавляется в `data_company`. Сам человек добавляется в `peopledb`, и в поле «конференции» записывается название текущей.

**Итого:** Word-файл → список строк → готовые записи в памяти → SQLite. База используется дважды: на шаге 2 для сверки («этот человек уже есть?») и на шаге 4 для записи. 

## Поиск дублей

Нужно понять, что `ООО «Аркадия»` и `Общество с ограниченной ответственностью «Аркадия»` это одна компания. Для этого названия нормализуются (юр. формы сокращаются), затем сравниваются через `rapidfuzz` (порог 85–90). Людей сравнивают по ФИО независимо от порядка слов, и компания тоже должна совпасть. Найденным людям присваивается их старый номер, и в интерфейсе они подсвечиваются зелёным.
